# Wisplight model-call cost audit (read-only, 29 September 2026)

Prices used (Bram's, per M tokens): Haiku 4.5 $1 in / $5 out, cache read $0.10, cache write $1.25. Sonnet 5 $2 / $10, read $0.20, write $2.50. Opus 5.5 $4 / $20, read $0.20, write $5. Minimum cacheable prefix: Haiku 4.5 4,096 tokens, Sonnet 5 1,024, Opus 5.5 512 (confirmed in the claude-api skill reference; shorter prefixes silently do not cache). Bram's roles: voice Haiku 4.5, brain Sonnet 5, chronicler Opus 5.5.

Sources: `src/engine/modelkinds.ts`, `src/node/ai/measured.ts` (measured tokens of the real trial of each kind), `tests/fixtures/model/*/` (usage per fixture), `src/node/ai/providers.ts`, `gateway.ts`, `guideprice.ts`, `pricing.ts`, the prompt builders per kind, and two measurements I ran with the mock model (no API calls): every kind's request captured through `kindSituation` (`src/engine/trials.ts`) to count system/prompt/schema characters, and a 3-game-day headless simulation of the Nethermarch in continue mode counting calls per kind and how stable each kind's system part is. Character counts are converted with the measured chars-per-token ratio of the same kind's real trial (2.1 to 3.0 chars/token; these prompts are dense with ids and YAML), so everything not labelled "measured" is an estimate.

## 1. Three corrections to what we thought

1. **Every kind sends a cache marker, not only the world steps.** `systemBlocks` (providers.ts:270) uses `cacheBreak ?? system.length`: without a cacheBreak the *whole* system part gets `cache_control: ephemeral`. So on every model the system is offered to the cache. On Haiku it is too short (see 2) so nothing happens. On Sonnet and Opus the system part is above the minimum for most kinds, which means **every cold call pays the 1.25x cache-write price on its system part** and only gets it back when the same system is sent again within 5 minutes. The app's usage overview shows `cachedPercent` (reads only), so a 0% reading hides the writes; `cacheWriteTokens` is in the usage store. The world-build fixtures (`tests/fixtures/worldbuild/quiet-reach`) prove the mechanism works when the prefix is stable: frame step write 18,381, every later step reads 18,926 cached.
2. **The talk line cannot cache on Haiku at all.** Its system part is ~2,000 tokens (5,812 chars measured in the trial situation; safety 956 chars + rules ~2,600 + world frame ~900 + the person's card ~1,300). The person's card is already inside the system. Haiku needs 4,096: the stable part would have to grow by ~2,100 tokens (~6,000 to 7,000 chars) of filler before anything cached. The 4,400 in / 0% cache in Bram's log is exactly this.
3. **The structured-output schema is billed as input on every call.** The chars/token ratio of the real trials only makes sense with the schema counted (npc_reply: 10,126 chars with schema / 3,481 tokens = 2.9; without it 2.3, implausible for English). The schema is rebuilt per call with per-call enums (topics, offers, keys), so it is part of the *changing* input. It is 22% of a talk line's input (2,229 chars), 15% of a goal choice (909), 15% of a night round (4,890 chars, of which `plans` 2,128).

Other provider facts (providers.ts:140-160): Opus 5.5 is `alwaysThinks` → no `thinking` param, `max_tokens + 4000`, effort only when the request sets one; **only `region_story` (medium), `map_paint` (low) and the world steps set an effort, so every other Opus call (chronicle, tides, journey, legends, weave, district, outline, expansion, land, far_place, builder_draft, world_enhance, palette_draft, voice_draft) runs at Opus 5.5's default `medium` with thinking on.** The `+4000` itself costs nothing (a cap), but the thinking tokens it makes room for are billed as output; from reply length vs output tokens I estimate them at roughly 900 of the chronicle's 2,243 output tokens, 1,300 of a district's 3,071, 600 of a land's 1,267, 450 of an expansion's 1,249, 140 of tides' 254, and ~0 for journey, legends, weave, far_place, outline (estimate). Sonnet 5 gets `thinking: disabled` (correct for Sonnet 5), Haiku nothing. No tools are sent. Nothing in the stable part varies per call (no timestamps, ids or seeds in `system`; `NOW:` and the scene go in `prompt`). One accounting gap: `upperBoundUsd` reserves `request.maxTokens`, not the `+4000`, so an Opus call can exceed its reservation by up to $0.08.

## 2. Frequency: what really runs in an hour

- The clock runs **one game minute per real second** (`src/main/index.ts` setInterval 1000 ms, `engine.tick(1)`), paused during a talk, combat, or idleness. An hour of play with 40 lines is perhaps 25 to 40 real minutes unpaused = 25 to 40 game hours = **1 to 1.7 game days**.
- **Goal choices**: only NPCs within 8 km of the player (`lod.ts` FULL_KM) think with the model; up to `people.goals_per_day` 6 per person, rest 5 game hours (= 5 real minutes), plus morning, news and signals. The 3-day simulation of the Nethermarch (31 NPCs, 16 within reach) made **141 goal calls in 3 game days: 34, 51, 56 per day, up to 13 per NPC**. That is **45 to 80 goal calls per real hour of play, not the 25 the guide price assumes.** In a real talk-heavy hour with the clock paused half the time, ~45; at the desk with the clock running, ~110.
- **Night round**: one run per game day at 04:00 (`storylines.ts nightly`), plus at most one `urgent` run per game day (belang ≥ 4; urgent runs are not held by the pacer), plus the pulse can ask for one. The pacer (`src/node/pacer.ts`, knob `night_round_minutes` = 20) allows a night run **up to 3 times per real hour**; with 1 to 1.7 game days per hour expect 1 to 2. In the simulation the night run's system part was byte-identical every night (21,912 chars) and it ran once a day from day 2; the real fixture used **no lookups** (`lookup: []`), so a night round is normally a single call.
- **Journey**: every overland travel, passage and "what changed since last time" paragraph is one Opus call (`engine.ts narrate`, `travel.ts`, `passages.ts`, `returning.ts`). Estimate 4 to 8 per hour of moving about; 0 when sitting in a talk.
- **Tides**: only on the first of a game month (30 game days = 12 real hours unpaused) or every 10 sessions, pacer 120 min: ~0.05 per hour.
- improvise (2/h), party_reply (2/h, only with companions), chat_line (1/h, only on `listen` at a long chat), lore_check (1 per night round with lore of belang ≥ 4): all estimates.
- Place-making kinds (outline, district, weave, far_place, expansion, land, region_story) and legends run once per new place / region / new game and are priced per event below.

## 4. Ranked savings (estimated saving per hour of play, guide assumptions in brackets, realistic frequency after)

1. **npc_goals: make the shared prefix cacheable across NPCs.** Reorder the system: safety, rules, world frame, goal catalogue, then `cacheBreak`, then CHARACTER / YOUR PEOPLE / STANDING. Prefix ≈1,400 tokens (over Sonnet's 1,024). Per call $0.0093 (with the hidden write) → $0.0058. Saving **$0.09/h [25 calls] to $0.20–0.35/h [45–80 calls]**. Risk: none to quality (same text, different order); needs a test that the prefix is byte-identical between NPCs of one land (it is per land already: `worldFrame(world.content, landOfNpc)`).
2. **npc_goals: fewer calls.** The guide assumes 25/h; the code makes 45–80/h because 16 NPCs are "full" within 8 km and each may choose up to 6 times a day at one game minute per second. Options: lower `people.goals_per_day` to 3 or raise `goal_rest_hours` (knobs, no code); or let only NPCs in the player's *area* (not 8 km) use the model and give the rest the rules. Saving at 45–80/h: **$0.15–0.35/h** (halving). Risk: NPCs far from the player choose less interestingly; the player rarely sees it. Also: a signal choice may cost two calls (question round then choice, `engine.ts:1010-1023`), fine as designed.
3. **Chronicle: effort `low` on Opus 5.5** (the kind sets none, so it runs at medium; thinking ≈900 of 2,243 output tokens, est.). Saving ≈$0.014 per round, **$0.014/h [1] to $0.03/h [2]**. Risk: medium; the night round is the most judgement-heavy call. Measure with `npm run trial -- --kind chronicle --record` at low and compare faithfulness before adopting. The same switch is clearly safe for the table-shaped Opus kinds: tides (−$0.003), weave, far_place, journey (no thinking measured anyway), palette_draft (−$0.04 per draft, it is a colour table), district (−$0.026 per district, est.).
4. **Chronicle: trim the stable input.** The night round sends the full CHRONICLER.md (~14,000 chars ≈ 5,300 tokens, 44% of its input) every night, plus a 4,890-char schema (≈1,800 tokens) of which `plans` (2,128 chars) matters only when a plannable line exists. A night-round-specific short guide (what the round needs: tone, three versions, storyline rules; not the whole book) of ~4,000 chars and a `plans` block only when `plannable.length` would cut ~5,000 tokens: **$0.020 per round, $0.02–0.04/h**. Risk: low if the guide's rules that the readers enforce anyway are what is cut; the world guide is Bram's text, so this is a content change per world (Skerrow and Deepwell too).
5. **Journey to the voice model (or brain).** A 60-word reword, checked by the engine word for word (names, word count, oaths), is a voice-tier task. Opus $0.0053 → Haiku $0.0013 (Sonnet $0.0027). At 4–8/h: **$0.016–0.032/h**. Risk: low; the checks throw a bad paragraph away and the rules' text stands. Journey has `priority: 'low'` but goes at Opus 5.5's medium effort and 60-second chronicler timeout for an 8-second call.
6. **npc_reply: trim the changing part.** The schema (2,229 chars, ≈750 tokens, 17% of Bram's 4,400) carries 27 `act` enum values and descriptions on every line; the rules (~2,600 chars) and the per-world "When it comes up / Not here" lines (in the prompt, static per world) could go to the system (they are stable) and shrink. A 20–25% cut of input: $0.00505 → $0.0040, **$0.04/h**. Risk: low-medium; each rule was added after a playtest, so trim by measurement (`npm run trial -- --kind npc_reply`) not by feel. Do not pad to 4,096 for Haiku caching: the write on the first line of each talk eats most of the read gain (net ~15% of talk cost, ~$0.03/h, at the price of ~6,500 chars of filler per call).
7. **Stop paying cold cache writes where nothing reads them.** With the whole-system marker, every Sonnet/Opus call above the minimum pays 1.25x on its system part: npc_goals +$0.001/call, chronicle +$0.008/round, journey +$0.0009, district/outline/expansion/land +$0.006–0.03 each, builder_draft/world_enhance +$0.02 each. Either set `cacheBreak` deliberately per kind (only where a read is likely within 5 minutes: the goals' shared prefix, the writing aid's contract, lookup rounds) and send no marker otherwise, or accept it where reads are likely. Saving at play: **≈$0.01–0.02/h** plus $0.02–0.05 per new place. Risk: none.
8. **Night rounds per hour.** The pacer allows one every 20 real minutes; with the clock at a game day per 24 unpaused minutes, an evening at the desk gets 2 to 3 rounds an hour, the guide prices 1. Raising `night_round_minutes` to 30 or 40 caps it at 1.5–2: **$0.09 per round avoided**. Risk: the world's news arrives a little later; nothing is lost (a later night adds to the waiting run, `requestRun`).
9. **Tides to Sonnet** (a bounded judgement: nothing / threat / event within rules): $0.0099 → $0.0049 per month; negligible per hour, but free.
10. **Editor: give builder_draft and world_enhance a cacheBreak** after the contract and guide (47,900 chars ≈ 17,000 tokens, identical between drafts of one session, `cacheHour` like the steps): saves ~$0.06 per repeated draft within the hour; costs $0.03 extra on the first. Out of play scope but the biggest single-call waste in the editor.

Not worth it: lore_check, chat_line, improvise, party_reply are already on the right model and under the cache minimum; their prompts are small.

## 5. Totals

Guide-price assumptions (40 lines, 25 goals, 1 night round + 1 lore check):
- now: talk $0.202 + goals $0.209 + night $0.095 = **$0.505 per hour** (the app's own `guidePrice` gives the same, without the hidden cache writes: +$0.03).
- after savings 1, 3, 4, 6 (no change in frequency): talk $0.160 + goals $0.146 + night $0.061 = **$0.37 per hour (−27%)**.

Realistic frequency for an hour at the desk (40 lines, 60 goals, 2 night rounds, 6 journeys, 2 improvisations, 2 party lines, 1 chat line, cold cache writes counted): **≈$1.02 per hour now**; after all savings including 2 (30 goals), 5 (journey on Haiku), 7, 8 (1.5 night rounds): talk $0.16 + goals $0.17 + night $0.09 + journey $0.01 + small kinds $0.01 = **≈$0.44 per hour (−57%)**. The two numbers that move the bill are the goal-choice count and the night-round count, not the price of a talk line.

## 6. Caveats

- Everything with a `≈` is an estimate from character counts at the measured chars/token ratio of that kind; the thinking-token split is inferred from reply length and should be confirmed with one recorded trial at `effort: 'low'`.
- The kind fixtures record `inputTokens`, `cachedTokens` and `outputTokens` only, not `cacheWriteTokens`, so the cold-write surcharge is read from the code path (`systemBlocks`), not from a fixture; the world-build fixtures do record writes and confirm the mechanism. Bram's usage store (`src/node/ai/usage.ts`) has `cacheWriteTokens` per model and can confirm it in a minute.
- Whether Anthropic places the structured-output schema before or after the system prefix in the cache order is not stated in the skill reference; if it were placed *before*, a per-call schema would break every cache including the world steps' — the world-build fixtures show reads of 18,926 with a per-step schema, so it does not.
- The simulation has no player: no talk lines, no journeys; its goal-call count is for a stationary player with the clock running.
